# 聊天记录分析插件 (Chat Analyzer)

定时收集群聊消息，提交给 AI 进行分析审核，帮助管理员快速了解群内讨论主题、氛围变化，以及是否需要介入处理。

## 功能特性

- **定时自动分析**：按配置的时间间隔，周期性收集聊天记录并提交 AI 分析。
- **关键词即时触发**：消息包含预设关键词时，立即触发一次即时分析（同一群有冷却时间，避免频繁触发）。
- **手动审核命令**：管理员可通过 `/analyze`（别名：`/审核`、`/分析`）手动对指定群发起即时分析。
- **双向消息采集**：同时收集群成员消息和 AstrBot 自身的回复，确保分析视角完整。
- **多群独立策略**：每个群可配置独立的分析策略组合（综合审核、主题分析、舆情监控、活跃度分析、风险检测），互不干扰。
- **静默模式**：当 AI 判断本轮聊天无异常时，跳过报告推送，减少通知噪音。
- **违规消息定位**：分析结果中自动提取需关注/需复核的消息编号，并通过合并转发消息展示原文，方便管理员快速定位。
- **持久化缓冲**：聊天记录缓冲区自动持久化到磁盘（每 10 条消息自动保存），插件重启后不丢失待分析消息。

## 快速开始

1. 将插件目录放入 AstrBot 的插件目录下，重启 AstrBot。
2. 在 WebUI 管理面板中启用插件（`chat_analysis_enabled` 设为 `true`）。
3. 配置「多群独立分析策略组」：添加策略组并关联群号，选择分析策略。
4. （可选）配置全局或策略组级别的报告发送目标，将分析报告推送到指定群。

## 安装

将插件目录放入 AstrBot 的 `addons` 或插件目录下，重启 AstrBot 即可。

```bash
# 通过 Git 克隆
cd astrbot/plugins
git clone https://github.com/makotowu/astrbot_plugin_chat_analyzer.git
```

## 配置

在 AstrBot WebUI 管理面板中对插件进行配置。

### 基础配置

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `chat_analysis_enabled` | bool | false | 是否启用插件 |
| `chat_analysis_interval_minutes` | int | 30 | 定时分析间隔（分钟），最小 1 分钟 |
| `chat_analysis_max_messages` | int | 0 | 每次分析最大消息数，0 表示不限制 |
| `chat_analysis_skip_silent` | bool | true | 无异常时跳过报告推送 |
| `chat_analysis_target_session` | string | 空 | 全局报告发送目标会话，格式如 `aiocqhttp:GroupMessage:群号`。留空则仅写入日志 |
| `chat_analysis_admin_ids` | string | 空 | 插件管理员 QQ 号（多个逗号分隔）。配置后除 AstrBot 内置管理员外，这些 QQ 也可使用审核和处置命令 |

### 策略组配置 (`chat_analysis_group_configs`)

在 WebUI 中可为不同群配置独立的分析策略组，每个策略组支持关联多个群，共享相同的分析策略。支持模板快速添加：

| 配置项 | 类型 | 说明 |
|--------|------|------|
| `group_ids` | string | 应用此策略的群号列表，多个用逗号分隔（如 `123456,789012`） |
| `presets` | 多选 | 启用的分析策略，支持：综合审核(default)、主题分析(topic)、舆情监控(sentiment)、活跃度分析(activity)、风险检测(risk)、自定义(custom) |
| `custom_prompt` | text | 自定义提示词，当 presets 包含 custom 时生效 |
| `action_mode` | radio | 处置模式：`suggest`(仅建议)、`confirm`(确认后执行)、`auto`(自动执行)。默认 `suggest` |
| `group_rules` | text | 群规文本，将作为参考依据提交给 AI，使分析结果更贴合实际情况。支持换行，留空则不注入群规 |
| `trigger_keywords` | string | 触发关键词，多个用逗号分隔。消息包含任一关键词时立即触发即时分析 |
| `target_session` | string | 该策略组的报告发送目标，留空则使用全局配置 |
| `admin_ids` | string | 策略组管理员 QQ 号（多个逗号分隔）。仅对此策略组下的群生效，可使用审核和处置命令 |

## 管理员权限

插件支持三级管理员：

| 级别 | 来源 | 权限范围 |
|------|------|----------|
| AstrBot 内置管理员 | `astrbot` 配置 | 全局 |
| 插件通用管理员 | `chat_analysis_admin_ids` | 全局 |
| 策略组管理员 | 策略组 `admin_ids` | 仅该策略组下的群 |

> - 策略组管理员可通过指令在群内动态添加：在被管理的群中 @ 目标成员 发送 `/策略组管理员`（别名 `/admin`、`/setadmin`）即可批量添加，修改会自动持久化到配置文件。
> - 每个群只能加入一个策略组，重复加入时自动跳过。
> - 当 AI 建议对**任意级别**管理员（AstrBot 内置 / 插件通用 / 策略组）执行处置时，系统会自动跳过处置并通过通知渠道提醒，避免误操作。

## 命令

| 命令 | 别名 | 权限 | 说明 |
|------|------|------|------|
| `/analyze` | `/审核`、`/分析`、`/analyze_now` | 管理员¹ | 手动触发指定群的即时分析 |
| `/策略组管理员` | `/admin`、`/setadmin` | 管理员¹ | 在群内 @ 成员添加为策略组管理员；或使用 `/策略组管理员 --sync` 一键同步群主+管理员列表 |
| `/执行确认` | `/execute_confirm`、`/执行` | 管理员¹ | 确认执行 AI 建议的处置操作 |
| `/执行拒绝` | `/execute_reject` | 管理员¹ | 拒绝执行 AI 建议的处置操作 |

> ¹ 管理员 = AstrBot 内置管理员 **或** `chat_analysis_admin_ids` **或** 策略组 `admin_ids`。

用法示例：
```
/审核 123456           # 分析群 123456
/analyze 123456        # 同上
/分析                  # 分析当前群（需在群内发送）
/策略组管理员 @成员     # 添加 @ 的成员为策略组管理员
/策略组管理员 --sync    # 一键同步当前群主+管理员为策略组管理员
/执行确认 12345678     # 确认执行编号 12345678 的处置建议
/执行拒绝 12345678     # 拒绝
```

## 处置模式

插件支持三种处置模式，在策略组配置中设置：

| 模式 | 标识 | 行为 |
|------|------|------|
| 仅建议（不执行） | `suggest` | AI 仅输出处理建议，不执行任何 QQ 操作。**（默认）** |
| 确认后执行 | `confirm` | AI 输出处置建议后，生成确认编号发送到目标会话，管理员使用 `/执行确认` 批准后执行（含撤回违规消息）。 |
| 自动执行 | `auto` | AI 分析完成后直接调用 QQ API 执行禁言/移除/拉黑并撤回违规消息，处置报告发送到通知群。 |

### 支持的操作

执行处置时，Bot 会在被处置的群内同步发送通知消息。

| 操作 | QQ API | 说明 |
|------|--------|------|
| 撤回 | `delete_msg` | 独立处置动作，AI 会在【处置建议】中显式列出；不会随禁言等自动附带 |
| 禁言 | `set_group_ban` | 禁言时长由 AI 根据违规程度判定（300-7200 秒） |
| 移除 | `set_group_kick` | 移出群聊（允许重新加群） |
| 拉黑 | `set_group_kick` (reject_add_request) | 移出群聊并加入群黑名单（拒绝再次加群） |
| 清空群昵称 | `set_group_card` | 将违规群昵称清空，恢复为默认昵称 |

> **推荐**：如配置了群规（`group_rules`），建议将处置模式设为 `confirm` 或 `auto`，让 AI 结合群规做出更精准的处置决策。使用 `suggest` 模式时插件会在日志中给出警告。

### confirm 模式流程

1. AI 分析完成，输出【处置建议】（如：`禁言 #3 600 刷屏影响阅读体验 | 别刷屏啦～`）
2. 系统按**被处置人员**拆分，每人独立 8 位数字编号；同一人的多项动作按类型分组展示：
   ```
   🚨 AI 建议对群 123456 以下处置:
   👤 张三(987654321)
     · 撤回消息: #3 刷屏影响阅读体验
     · 禁言: #3 刷屏影响阅读体验（600s）
   
   请管理员确认:
     /执行确认 12345678
     /执行拒绝 12345678
   (编号有效期 60 分钟)
   ```
3. 管理员回复 `/执行确认 12345678` 或 `/执行拒绝 12345678`
4. 同一人的多项违规合并生效；不同人独立编号，可分别执行或拒绝

## 分析策略说明

插件内置 5 种分析策略，各策略专注于不同维度：

| 策略 | 标识 | 关注重点 |
|------|------|----------|
| 综合审核 | default | 整体讨论主题、氛围判断、异常行为、违规内容、处理建议 |
| 主题分析 | topic | 话题占比、话题是否偏离群定位、是否出现敏感/引战话题 |
| 舆情监控 | sentiment | 整体情绪走向、负面信号识别、情绪是否影响群秩序 |
| 活跃度分析 | activity | 互动模式判断、刷屏/灌水/复读检测、单人霸占话题识别 |
| 风险检测 | risk | 广告导流、违法违规、人身攻击、隐私泄露等严格内容审核 |

每个群可自由组合多个策略，AI 会综合各维度输出分析报告。

## 报告结构

AI 分析报告按以下格式输出：

```
【总体结论】 正常 / 需关注 / 建议复核
【摘要】 当前话题、氛围和最值得关注的点
【风险与依据】 抽象风险判断
【处理建议】 管理建议
【定位清单】 需关注或复核的具体消息编号及原因
```

当开启静默模式且本轮无异常时，报告将被跳过，不会推送。

## 运行要求

- AstrBot >= 4.5.2
- 已配置可用的 LLM 提供商

## 项目结构

```
astrbot_plugin_chat_analyzer/
├── main.py               # 插件入口：生命周期、事件处理、命令调度
├── metadata.yaml         # 插件元数据
├── _conf_schema.json     # 配置 Schema（WebUI 表单定义）
├── .gitignore
├── LICENSE
└── core/                 # 核心模块
    ├── constant.py       # 常量：提示词、正则、标签、冷却时间
    ├── models.py         # 数据模型：GroupConfig、ChatRecord
    ├── config.py         # 配置解析与持久化
    ├── prompt_builder.py # 提示词构建：策略组合、安全规则注入
    ├── image_processor.py # 图片处理：提取图片 URL 并转述为文字
    ├── ai_client.py      # AI 调用客户端：封装 LLM 请求
    ├── analysis_engine.py # 分析引擎：编排分析全流程
    ├── analysis_parser.py # 结果解析：结论提取、处置建议、安全清洗
    ├── buffer_manager.py  # 缓冲区管理：消息增删与持久化
    ├── action_executor.py # 处置执行：禁言/移除/拉黑/清昵/撤回
    ├── admin_manager.py   # 管理员管理：三级权限校验
    ├── report_sender.py   # 报告发送：构建头部、推送报告、合并转发
    └── utils.py           # 工具函数：时间范围、会话信息格式化
```

> 运行时缓冲区数据通过 `StarTools.get_data_dir()` 保存到 AstrBot 标准数据目录（`data/astrbot_plugin_chat_analyzer/buffers.json`），与插件源码分离。
